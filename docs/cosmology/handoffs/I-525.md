## Why this exists, and why it is before porting

The new package is built beside legacy `tidal`, and **new code never imports old code**
(test-enforced). So how do we ever check the new `derive` reproduces the old physics?

**By freezing legacy's outputs as committed data, once, now** — before any porting starts.
New-package tests then assert against *files*, never against a live legacy import or
subprocess. Two consequences make this the load-bearing step it is:

- **It decouples port order from deletion order.** Because the oracle is data rather than
  live code, `tidal/inference/` can retire at M1b instead of waiting for M6
  (`repo_reshape.md` §7, "why early deletion is safe").
- **A test that reaches into legacy is how the oracle becomes undeletable infrastructure**
  (§8). That is why `tests_cosmo/` is inside the boundary test's scope, and why your
  fixtures must be self-contained data.

`scripts/oracles/` is **the single place in the repository allowed to touch legacy**. It
runs once, produces data, and is not imported by anything.

## What to freeze

For each theory in the example corpus, **four artifact kinds**:

1. **The derived spec JSON** — copied, not regenerated.
2. **`tidal inspect --detail summary`** output.
3. **`tidal inspect --families`** output.
4. **`tidal validate` verdicts — BOTH plain and `--stability`**, as two separate artifacts.

> **Amendment (2026-09-06, from the I-525 session's own finding).** This list originally
> said "`tidal validate` verdicts (with `--stability`)", i.e. the `--stability` run only.
> **That would have produced a near-vacuous oracle.** Measured over the corpus:
> `--stability` errors with *"cannot evaluate symbolic coefficient … is not defined"* on
> **39 of 48** specs — free parameters with no defaults — while plain `validate` returns a
> real **29 pass / 19 fail** split. §5.1's gate is "same verdicts on the example corpus",
> and a verdict about missing parameter defaults is not a verdict about the physics.
> Freeze both; the extra runtime is about a minute.
>
> **`--families` added** for a different reason: family and index structure is *invariant
> under the renaming* #513 introduces, while prose summaries are not, which makes it the
> artifact best suited to M3's semantic-mapping work (§5.2). ~130 tokens per spec.
>
> ### The finding that matters more than the artifact list
>
> **18 of the 19 plain-`validate` failures are #397** — `a_0`/`a_1` opposite effective
> self-laplacian orientation, from 25 committed JSONs that predate the #381 `a_0` sign fix.
> **That issue is open.** (The 19th, `torsion_gertsenshtein_exact.json`, fails to load on
> `time_order > 2`.)
>
> So for those 18 specs, **"same verdicts" is the wrong equivalence gate.** The new package
> re-derives them and *should* produce a different, correct verdict. Record this in the
> oracle README explicitly: **legacy fails these 18 under #397; a port that passes them is
> the fix, not a regression.** Without that written down, M3 is either blocked by a gate it
> ought to fail, or papers over the difference silently — and §5.2 makes the written mapping
> *part of the gate*, not commentary on it.

**Not** measured scalars, and **not** reference `C_ℓ`/transfer arrays — see the amendment
in §8 for why both were removed from this list (legacy is flat-space and cannot produce a
`C_ℓ`; and `simulate`/`measure` are re-implemented or dropped, so an oracle for them gates
nothing that survives).

## How to enumerate the corpus — this part has a trap

**Build the list from `examples/*/theory*.toml` paired with its committed spec JSON** (the
TOML's `output` path). There are 46 valid pairs.

> **⚠ Amendment (2026-09-06, from this session) — the trap section contained the trap.**
> The glob above **does not produce 46 pairs**. `examples/*/theory*.toml` matches 48 files
> and silently drops **`examples/curved_spacetime/conformal_static.toml`**, which does have a
> committed spec — 45, not 46 — in exactly the way this section warns about for
> `run_examples.sh`. It also makes the exclusion list below incoherent: under that glob
> `de_sitter.toml` is not a candidate, so it cannot be "excluded" and only three exclusions
> exist. **The count and the four exclusions are right; the recipe is not.**
>
> **Use instead:** enumerate `examples/*/*.toml`, keeping every TOML whose `[output].path`,
> resolved *relative to the TOML's own directory* (`tidal/cli/_derive.py:6305-6310`), ends in
> `.json` — exactly **50** TOMLs, of which **46** have a committed spec. The `.json` test is
> what drops the five `sweep_*.toml` files, whose `[output].path` is a directory. Never filter
> on the `theory` filename prefix: `conformal_static.toml` and `de_sitter.toml` are theory
> derivations that do not carry it.
>
> Amended at the other instruction site too (`repo_reshape.md` §8) and on GH #525, whose
> existing comment repeats the same glob.

- **Do not use `scripts/run_examples.sh`.** It is stale: it enumerates ~13 example
  directories that no longer exist and would silently *skip* them, so a corpus built from
  it would be quietly incomplete.
- **Do not use `examples/*/run.sh`.** Those end in `tidal plot` steps, which are a `drop`
  row scheduled for removal (#533) — a dependency on them would break this task's own
  reproducibility gate later, with no merge conflict to warn anyone.
- **Four TOMLs have no committed spec** — `curved_spacetime/de_sitter.toml` and the three
  `gertsenshtein` dipolar/radial variants. Deriving them needs Wolfram, which you do not
  have this wave. **Exclude them by name, with the reason recorded in the script and the
  README** — not silently.

## Two hard constraints on the committed fixtures

1. **No absolute paths.** `tests/test_repo_hygiene.py` checks `tests_cosmo/`, so a
   `.resolve()`d path landing inside a captured artifact fails the whole suite. Legacy
   logs resolved paths in places (`_simulate.py` around lines 1447/2874/2940) — check what
   actually reaches your artifacts.
2. **Scrub volatile fields and document the scrub**, because the gate is a byte-stable
   re-run. Timestamps, hostnames, durations, absolute paths. The spec JSONs carry a
   `derivation_hash` and no timestamps, which helps.

## Success criteria — verified from artifacts

1. `scripts/oracles/` runs end to end from clean and exits 0.
2. **Re-running it reproduces the committed fixtures byte-for-byte** after the documented
   scrub: `git diff --exit-code` clean. The orchestrator re-runs this independently, and
   again after I-524 merges.
3. **All five artifacts** present for all 46 pairs (spec JSON · `inspect --detail summary` ·
   `inspect --families` · plain `validate` · `validate --stability`); the four exclusions
   named with reasons; the #397 correspondence recorded in the README.
4. `uv run pytest tests/ tests_cosmo/ -q` green — in particular the boundary test and
   repo-hygiene (which is what catches a stray absolute path).
5. `ruff`, `pyright`, `cspell` clean on what you touch.
6. Nothing under `tidalcosmo/` or `tests_cosmo/` imports or shells out to legacy — only
   `scripts/oracles/` may.
