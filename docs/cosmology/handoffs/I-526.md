## What to build

### 1. `scripts/install-psalter.sh`

Model it on `scripts/install-xact-xcoba.sh`, which already has the right shape: colored log
helpers, a `check_wolfram` guard, and a `get_wolfram_user_dir` that **queries
`$UserBaseDirectory` through `wolframscript`** rather than hardcoding a path — required, no
environment-specific absolute paths in committed files.

1. `git clone` PSALTer at a **pinned commit** (default `bb45adb0`, overridable by env var).
2. Copy `xAct/PSALTer` into `$UserBaseDirectory/Applications/xAct/`. That is the install.
3. **Write the resolved commit hash to `INSTALLED_COMMIT`** inside the installed directory.
   The exporter reaches into private symbols, so the installed revision is a *correctness*
   input, not bookkeeping.
4. Inkscape: `apt-get install` it, warn and continue on failure — it is not needed.
5. Verify `Needs["xAct`PSALTer`"]` loads and `DefField`/`ParticleSpectrum` exist. **Allow a
   generous timeout** — the first load builds SPO tables and is slow.

Add a PSALTer section to `scripts/verify-wolfram-setup.sh` doing step 5 plus a `DefField`
smoke test, so the check survives independently of the installer.

### 2. The Tier-1 install gate

**Run a small theory first** (the published `VectorTheory` scale) to confirm the install
works end to end before committing to the expensive one. Then Tier 1 proper:

- Run `ParticleSpectrographCTEG.m` **unmodified** (fetched via
  `scripts/research/psalter_stage1/fetch_reference_sources.sh`, which pins the revisions —
  **never commit the payload**, only the route).
- Load the committed `ParticleSpectrographCTEG.mx` and **diff the two associations
  key-by-key.**

This gates the install because **both the input and the expected result are the author's**,
so a mismatch can only be the install. (Tier 2 mixes install correctness with our own
authoring and does not localize — it is the *physics* gate, and it is not yours.)

**Its runtime has never been measured.** Take checkpoints at **~1 h** and **~8 h**; if it is
still running at 8 h, report that plainly with the partial trace rather than pressing on
silently. A "did not terminate" result with a checkpoint trace is a real deliverable.

### 3. The three live-install probes

- **#521 — is `Method` inert?** `OptionValue@Method` appears nowhere in the package on a
  static read, but an option consumed through `xAct`xPlain`` or an inheritance path would
  not show up that way. **Run one small theory both ways** and check results *and* timings
  are identical. Report as "`ParticleSpectrum` wall time, `Method` inert" — **never** as an
  Easy-vs-Hard comparison.
- **#522 — the missing-coupling probe.** Feed PSALTer a term with a bare numeric
  coefficient. **The expected outcome is silence** — record that it is silent, and capture
  the `UnknownCoupling` message text (which *is* thrown, for a genuinely undeclared symbol)
  so our own validator hint can echo it.
- **#523 — the harvest surface.** Confirm `ParticleSpectrum.m` writes exactly two
  association keys (`WaveOperator`, `PseudoDeterminant`) and that the remaining content
  lives in the private `$Local*` globals. *(Note: §0.4 lists eight of these and §5 lists
  six as the exporter's input surface — confirm which is right on the live install and
  record it; the discrepancy is unresolved on paper.)*

Commit the two small upstream `.wxf` fixtures under `tests_cosmo/fixtures/psalter/` with a
`PROVENANCE.md` (source repo, pinned revision, file hashes, the D6 permission note, and the
observation that these are *data outputs*, not GPL sources — flagged on #495 for the
release-time review regardless). They let the Python reader be tested **without Wolfram
installed**, which is the property that matters.
