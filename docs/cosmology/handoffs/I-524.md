## What to build

1. **Package entry points.** `tidalcosmo/__init__.py` and a minimal `tidalcosmo/cli/`
   sufficient for a console script. Setuptools' `packages.find` needs `__init__.py`, and
   the import check below needs something importable. Keep the CLI to `--version` and
   `--help`; **no subcommands, no physics** — `cli/README.md` says no physics lives there
   and that holds from the first line.
2. **The second console script.** Both CLIs coexist during the transition (D3): `tidal`
   stays exactly as it is, `tidalcosmo` is added alongside.
3. **Extras.** `camb` and `cobaya` as optional dependencies. Neither is currently
   installed, and M1a onward cannot start without them. Check what the existing
   `[project.optional-dependencies]` block does and follow its shape.
4. **YAML package-data**, so Cobaya's dotted-path packaging can find preset YAMLs later.
   `pyproject.toml`'s `include = ["tidal*"]` already matches `tidalcosmo`; the change is
   package-data, not discovery.
5. **The CI lane — and make it able to fail on this branch.** `.github/workflows/test.yml`
   currently triggers only on `pull_request` → `main`. Nothing runs on a delegate branch or
   on merges into `feat/cosmology-program`, so "the lane is green" is currently unverifiable
   at merge time. **Add a `push` trigger for `feat/cosmology-program`** (and
   `workflow_dispatch` if useful). This is the point of the item — a CI lane nobody can
   observe is not a gate.
6. **Port `error_with_hint`** from `tidal/cli/_console.py` into the new package. It is a
   `port` row in `repo_reshape.md` §5.6 with no milestone, so §7 would sweep it into M6 —
   but the WS6 config validator needs it much earlier, and it is small. **Port, do not
   import** (D3): move it with its docstring, and record the origin as
   `Ported from tidal/cli/_console.py` per §5.7's provenance rule. Every user-facing error
   in the new package uses it from the start.

## Success criteria — quantitative, verified from artifacts

State these before you write code; the orchestrator re-runs all of them at merge:

1. `uv sync --all-extras` succeeds from clean, and `python -c "import camb, cobaya"` works.
2. `python -c "import tidalcosmo; print(tidalcosmo.__version__)"` works, and the
   `tidalcosmo` console script runs `--version` and `--help`.
3. `uv run pytest tests/ tests_cosmo/ -q` — **both suites green**, including
   `tests_cosmo/test_package_boundary.py` and `tests/test_repo_hygiene.py`.
4. `uv run ruff check`, `uv run ruff format --check .`, `uv run pyright` — all clean. The
   new tree starts with **no ruff per-file-ignore blanket and strict pyright**
   (`repo_reshape.md` §8); do not inherit the legacy exemption surface.
5. `cspell` clean on every file you touch.
6. **The CI lane demonstrably ran on your branch** — link the run. This is the criterion
   that distinguishes "I edited the workflow" from "the workflow works".

Add tests under `tests_cosmo/` for the CLI surface and the ported `error_with_hint`.
